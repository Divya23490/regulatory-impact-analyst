# Theme 3: Digital Operational Resilience Testing

## Regulatory Requirements
- Financial entities (other than microenterprises) must establish, maintain, and review a sound and comprehensive digital operational resilience testing programme as an integral part of their ICT risk management framework [dora::art24::p1].
- The testing programme must follow a risk-based approach and include a range of assessments, tests, methodologies, practices, and tools such as vulnerability assessments and scans, open-source analyses, network security assessments, gap analyses, physical security reviews, source code reviews, compatibility testing, and penetration testing [dora::art24::p3, dora::art25::p1].
- Specific entities are required to perform vulnerability assessments prior to deploying or redeploying critical applications and infrastructure [dora::art25::p2].

## Affected Internal Policies
- [policy::POL-007] — Penetration Testing Standard: Focuses on annual external penetration testing of internet-facing systems, but lacks a comprehensive testing programme covering vulnerability assessments, source code reviews, and scenario-based testing across all ICT assets.
- [policy::POL-001] — ICT Risk Management Framework: Lacks integration with a structured, multi-faceted resilience testing programme.

## Gap Analysis
- **Testing Programme Scope**: POL-007 is limited to annual external pen tests; it lacks the broader suite of required tests (vulnerability scans, open-source analyses, network security assessments, physical security reviews) mandated by DORA Art. 25(1).
- **Risk-Based Planning**: The bank lacks a formalized, periodic review process for the testing programme based on evolving ICT risk landscapes and asset criticality [dora::art24::p3].
